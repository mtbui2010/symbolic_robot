# Protocol suite (factory): three engine options on a simulated factory floor

Written before the first full run (in the earlier repository this text came from; this copy is adapted to the factory domain only, the household half of the original protocol is not part of this suite). Its sha256 is recorded in `<results dir>/PROTOCOL_SHA256` by `python -m bench run`; the file must not change after that.

## Question
Do three recent, default-off options of the `robot_agent` engine help on a simulated factory floor? Everything here is **simulation**: no UI, no real robot, a scripted person.

* `ask_source`: ask "Where is the X?" first when the request names no location.
* `ask_source_reask` (reask on miss): if the person named a place and the first look there does not see the object, ask once more; not after "I do not know".
* `search_route_weight` 0.3 (vs 0): look at nearer likely places first (uses the ENV `loc`).

## Engine and models
Engine: `~/trung_workdir/robot_agent`, branch `live/no-ros`, working tree with uncommitted edits (the newest code); the commit and the list of modified files are to be recorded with the results (`ENGINE.txt`). Not edited.
LLM: the user's Ollama (`127.0.0.1:11434`), model `hl-understand-p3-s700` for reader, planner and translator (`--models single`). A LoRA trained on household vocabulary only.

## Domain
* **factory**: the `factory` domain, floor `assembly_hall` (9 work zones and an aisle, 25 places of which 24 are on the robot's map, 21 objects, up to 40 m between places), `symbolic_robot.domains.factory` simulator. Profile `real`: detector miss 10 %, grip slip 5 %, drop 3 %, transient hardware fault 2 % per call, persistent fault in 4 % of episodes (`symbolic_robot/domains/factory/profiles/real.yaml`).

## Tasks (generated by `symbolic_robot/domains/factory/tasks_gen.py`, task seed 7, nothing hand-picked)
36 tasks. Objects are all objects of the world that the robot can carry and that are not in a locked container; destinations are surfaces that can hold objects. Objects are shuffled and paired with random destinations, two rounds when needed, no (object, destination) pair twice.
* Every 6th task (6 of 36) names the source: "Take the X from S to D." Answer policy: none.
* The other 30: "Put the X on D." (no location of the object). The simulated person's answer policy, one third each (10 tasks): **knows** (the true place), **unknown** ("I do not know."), **wrong** (a real place where the object is not; asked again, the true place).
* The same scripted person answers every other question: a where-question about a destination gets the destination; a confirmation gets "Yes."; "which" gets the object's name.
The person's script is written for this repo; no scoring rule or data of any benchmark is used.

## Arms (identical tasks, identical simulator seeds per task)
| arm | ask_source | reask_on_miss | search_route_weight |
|---|---|---|---|
| A | 1 | 0 | 0 (the old behaviour) |
| B | 1 | 0 | 0.3 |
| C | 1 | 1 | 0.3 |
| A2 | 1 | 0 | 0 (repeat of A: the noise of the whole pipeline) |

Options are sent as run options with each run (they override the environment), so one server serves all arms and drift hits all arms alike.
Per (task, repeat): the simulator seed is `task_number*100 + repeat` for every arm (so faults are paired). Repeats: 2. Episodes: 36 x 4 x 2 = 288.
Arm order within a (task, repeat) rotates with the task number. Each episode starts with `reset_world` (objects in place, robot on its dock, object memory, world state and grace memory files erased). Episode timeout 420 s wall (then cancelled, counted as failed). If one episode takes more than 40 s wall on average, tasks are cut to 24 (it does not: see the report).

## Measures (from the simulator's truth, never from the robot's claim)
* **success**: the goal object is at the destination place at the end.
* **wrong-done**: the engine says `done` with status `success` and the truth says not.
* **distance**: metres travelled, the sum of the legs of successful `move` calls in the simulator's call log (straight lines between places).
* **questions**: number of questions the robot asked (listen events). Also the number of where-questions about the object.
* **t_sim**: simulated seconds. Also the engine's own status, wall seconds, events.

## Analysis (`bench/suites/factory/analyze_protocol.py`)
Unit: the task (measures averaged over the 2 repeats). Paired differences arm minus A (and A2 minus A for noise): mean with a 95 % bootstrap interval (10000 resamples of tasks, seed 0). Sign test (exact, two-sided, ties dropped) on the **combined** per-task criterion: success rate higher = win, lower = loss; equal success: distance lower by more than max(0.5 m, 5 % of A's) = win, higher by more = loss. Also sign tests on success alone and distance alone. Breakdown per answer policy (knows, unknown, wrong, request names the source). Distance among tasks where both arms succeeded in every repeat is reported separately.

**Pre-registered win rule**: B or C beats A when it wins on more tasks than it loses on the combined criterion, **and** the mean paired difference of wrong-done is not above 0. The A/A difference tells how large a difference can come from noise alone; a "win" no larger than that is called noise. No correction for the two comparisons (B, C); reported as is.

## Generalisation probe (factory only)
The same 36 factory tasks, arm A, 1 repeat, with the stock reader `qwen3-vl:8b-instruct` (`ROBOT_AGENT_UNDERSTAND_MODEL`) versus the LoRA reader (the main run, repeat 0 of arm A). Planner and translator stay the LoRA model. Run last (loading another 8B model may evict the LoRA from the GPU).

## Pilot and fixes
3-5 episodes first; every failure inspected for bugs of the sim, adapter or runner (fixed before the full run, listed in the report); genuine robot or model behaviour is reported, not patched. The engine is not edited.

## Limits stated in advance
Simulated person, scripted answers; the factory simulator is mine and small, not a real plant; 36 tasks and 2 repeats make small effects invisible; the LoRA model was trained on household words only; the engine options were tuned on a household simulator, not on this one.
