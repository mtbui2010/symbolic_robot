# Known pitfalls

!!! abstract "In this page"
    - The behaviours of this repo that surprise people, grouped by what you are doing: start a server, run a benchmark, read a result, send a `sim_command`, use the core, follow the repo's rules.
    - For each one: the symptom, the cause with a permalink, how to avoid it, and the page that explains it.
    - All of it is **current behaviour at commit `a5cc7a4943aa`**. The identifiers F1 to F13 are the numbers the pages of this site use for the findings; other entries have no number.

Each entry was checked against the code. "Run" means it was run offline on a copy of the pinned commit; "read" means the code was read and not run (the task data and robot_agent were not available).

## Starting a server

| pitfall | symptom | cause | how to avoid | page |
|---|---|---|---|---|
| **F4** no friendly message without robot_agent | `python -m symbolic_robot run --robot factory` ends in a traceback `ModuleNotFoundError: No module named 'robot_agent'`, exit 1, not the exit 2 of other start errors. A `connections.json` is left in the run folder (run) | `cmd_run` catches `ImportError` only around `from . import server`, which works because `server.py` imports robot_agent inside `build()`. The import at [server.py:144](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/server.py#L144) happens inside the `try` of [cli.py:46-51](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/cli.py#L46-L51), whose `except` lists `RuntimeError`, `KeyError`, `ValueError` | install the `server` extra and robot_agent first; set `ROBOT_AGENT_DIR` for `make` | [Server glue](../modules/server-and-cli.md) |
| **F11** the headless ask is always English | a household or factory question asked in another language reaches the listen call as English | `ask_typed` has a `lang` parameter but passes the literal `"en"` to `listen_dashboard` ([server_skills.py:71](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/server_skills.py#L71)) | none in this repo; do not rely on the question's language reaching the listen call | [Server glue](../modules/server-and-cli.md) |
| **F13** two readiness checks | `make run` says "up" before the bench front end would call the same server ready | `make run` polls `/agent/mobile_pose/get` ([Makefile:67](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/Makefile#L67)); the front end polls `/agent/sim_world/get` and then waits a further 10 s ([orchestrate.py:37-48](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/bench/orchestrate.py#L37-L48)) | after `make run`, wait a few seconds before the first run | [Make targets](make-targets.md) |
| the Makefile listens on every address | `make run` serves on `0.0.0.0` while `python -m symbolic_robot run` alone serves on `127.0.0.1` | the Makefile default is `HOST ?= 0.0.0.0`; the command's default is `--host 127.0.0.1` ([Makefile:20](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/Makefile#L20), [cli.py:78](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/cli.py#L75)) | pass `HOST=127.0.0.1` when the server must stay local | [Make targets](make-targets.md) |

| **F8** `--dry-run` accepts an unknown arm | `--arms Z --dry-run` prints a plan line and exits 0 (run) | arms are checked in `run_campaign` ([campaign.py:23-25](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/bench/campaign.py#L23-L25)), after the dry-run return | read the arm names yourself; a real run stops with `unknown arm(s) [...]` before any episode (run) | [The bench front end](../modules/bench-front-end.md) |
| **F10** campaign arms always ask for the planner `sage`, in English | the arms of a factory campaign compare run options of one planner; no other planner is driven | the WebSocket message is `{"prompt", "lang": "en", "planner": "sage", "options"}` ([runner.py:26](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/bench/runner.py#L26)) | to compare other planners use the household benchmark | [Campaign runner](../modules/campaign-runner.md) |
| **F12** `make test ROBOT=home` selects by keyword | the target runs `pytest -k home`, not "the home folder" | [Makefile:94-95](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/Makefile#L94-L95): `-k $(ROBOT)` when `ROBOT` is not `factory`; with the default `ROBOT=factory` it runs every test (printed with `make -n`) | for one folder, call `pytest tests/home` yourself | [Make targets](make-targets.md) |
| `python -m bench list` needs `websockets` | `ModuleNotFoundError: No module named 'websockets'` even for `list` (run) | [bench/cli.py:12](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/bench/cli.py#L12) imports `campaign`, which imports `runner`, which imports `websockets` at its top | install the `bench` extra. `python -m bench.suites.home.cli planners` needs no websockets | [The bench front end](../modules/bench-front-end.md) |

| a changed protocol file stops a run | `SystemExit: the protocol changed after its hash was recorded` | the hash in `PROTOCOL_SHA256` no longer matches ([protocol.py:15-28](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/bench/protocol.py#L15-L28)) | restore the file or start a new folder; `--allow-protocol-change` overrides and keeps the old hash | [Campaign statistics](../modules/campaign-statistics.md) |
| a task file that differs from the packaged data is refused | exit 2 with `StaleTasksError` | `check_fresh_tasks` compares every record of a `--tasks` file with the packaged one ([runner.py:126](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/bench/suites/home/runner.py#L126)) | regenerate the file with `tasks-file`, or pass `--allow-stale` knowingly | [Household runner](../modules/home-runner.md) |
| `--limit` is a prefix, not a sample | a `--limit` run has a different mix of task kinds than the full split | it takes the first N tasks in file order and is marked `smoke: true` | quote `success_reweighted`, or run the whole split | [Household runner](../modules/home-runner.md) |
| a crash rate above 5 % | the run exits 4; scores are printed | more than `ERROR_RATE_MAX = 0.05` of the episodes ended with status `error` | read `errors_by_type`; do not quote the scores as a planner result | [Household runner](../modules/home-runner.md) |

## Reading a result

| pitfall | symptom | cause | how to avoid | page |
|---|---|---|---|---|
| **F9** the headline interval is task-clustered | `success_ci95` in `summary.json` and `report.md` differs from a plain Wilson interval of the same successes. In the oracle smoke run: 33 of 40 gives plain `[0.6805, 0.912546]`, headline `[0.667847, 0.917035]` with `n_eff` 34.5 (run) | the headline is a Wilson interval at the effective sample size, because the seeds of one task are not independent ([metrics.py:48-74](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/bench/suites/home/metrics.py#L48-L74)). The plain interval is kept as `success_ci95_episode`. The framework guide's "Wilson interval" is right; the code refines it | quote the clustered one and say so; with one seed per task the two are equal | [Metrics, report and compare](../modules/home-metrics-and-report.md) |
| `summary.json` differs between two checkouts of the same code | a byte difference in `config.versions` | it holds `git describe --dirty` of the packages | compare `episodes.jsonl`, or ignore `versions` | [Result files](result-files.md) |
| a rate of 1.0 or 0.0 on a smoke run | `rejection_rate` 1.0 | a tiny denominator: the oracle smoke run has 2 episodes of kind `refuse` | read the count before the rate | [Metrics, report and compare](../modules/home-metrics-and-report.md) |
| a run folder holds task text | records with `instruction_heard`, `final_say`, `refusal_texts`; factory `detail/` files | the task data goes into the records | publish aggregates only | [Result files](result-files.md) |

## Sending a `sim_command`

| pitfall | symptom | cause | how to avoid | page |
|---|---|---|---|---|
| **F5** `reset` ignores `what` | `reset` with `what: "objects"` also puts the robot back (run) | `what` is checked against `objects`, `robot`, `all` and then not used; `LiveBackend.reset` rebuilds the whole episode ([simcommand.py:52-61](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/simcommand.py#L52-L61)) | send `reset` only for a full new episode | [sim_command ops](sim-command.md) |
| **F6** the factory reports the variant under `color` | an object that is a large wrench has `'color': 'large'` (run) | `snapshot` fills `color` from the object's `variant` ([factory/world.py:143](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/domains/factory/world.py#L143)), and a variant is a size | read `label` for the variant; the household's `color` is a real color | [Live backend and sim commands](../modules/live-backend-and-sim-commands.md) |
| `truth` with `last: 0` returns the whole log | 4 entries logged, `last` 0 returned 4 (run) | the log is cut with `log[-last:]` ([simcommand.py:50](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/simcommand.py#L50)) | ask for `last >= 1` | [sim_command ops](sim-command.md) |

## Using the core

| pitfall | symptom | cause | how to avoid | page |
|---|---|---|---|---|
| **F1** `CallDraws` is a core helper that no domain uses at this commit | you read about `CallDraws` and find no domain calling it | the factory draws with `Rng`; the household has its own `Streams` and a vector of 14 slots. The only caller is [tests/test_core.py:33](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/tests/test_core.py#L33). It is exported by [`symbolic_robot/__init__.py`](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/__init__.py) for new domains | for a new domain, pick `Rng` (key per event) or `CallDraws` (one vector per call) on purpose; both are common random numbers | [Results, time and draws](../modules/results-time-draws.md) |
| **F2** the household domain uses almost none of the core | the household domain imports only `BaseDomain` from the core; it has its own random streams, clock, profiles and `SkillResult` | [domains/home/domain.py:10](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/domains/home/domain.py#L10) is the only import of a core module in the household package (grep, run) | do not expect a change in `symbolic_robot/rng.py`, `clock.py` or `profile.py` to move the household simulator | [Household domain and houses](../modules/home-domain-and-houses.md) |
| `Rng` keys that look different draw the same | `Rng(1).uniform("a", "b")` equals `Rng(1).uniform("a|b")`, and `uniform(1)` equals `uniform("1")` (run) | the key is the parts turned to text and joined with a vertical bar ([rng.py:21](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/rng.py#L21)) | keep key parts free of the bar and use a fixed shape | [Results, time and draws](../modules/results-time-draws.md) |
| changing a key's text changes old seeds | the same seed meets other faults | the key text is part of the hash | treat key text as part of the result format | [Results, time and draws](../modules/results-time-draws.md) |
| `Profile.get(key, None)` has no default | `KeyError` although a default was given (run) | the fallback applies only `if default is not None` ([profile.py:32](https://github.com/mtbui2010/symbolic_robot/blob/a5cc7a4943aa/symbolic_robot/profile.py#L32)); `0` and `False` do work | test `key in profile.keys()` first | [Profiles](../modules/profiles.md) |
| `with_overrides` keeps the old source label | an overridden number still says where the original came from | it changes `value` only | note the override where you report it | [Profiles](../modules/profiles.md) |
